## Start with SKU 209

Read the [reference part README](../parts/packaging_takeaway_container_rectangle_100_ml_capacity_109_mm_width_86_mm_height_29_mm_depth_tamper_evident_systempak_209/README.md) and open both PNGs beside it. The open portrait shows the inside, short-end tab and a raised lid. The seated view shows the lid flush with the collar. Match the visible construction and frame both objects fully. Use the actual SKU material and colour.

The 100 ml pot measures **108 × 86 × 27 mm bare** and **109 × 86 × 29 mm closed** (length × width × height). The former comes from the SKU sheet and the latter from the listing. The CAD uses X across the short side, Y along the long side, and Z up from the floor. Its radius, wall, skirt, taper, foot and tab are photo estimates. The profile records where each figure came from. Inspect the [editable parameters](systempak/209.json), [cross-section and lid](systempak_rectangle.scad), [builder and checks](../systempak_model.py) and [Blender scene](render_pot.py).

## Build the queue from the supplier snapshot

1. From the repo root, use `harvest_systempak(refresh=False)`, `product_to_oomp(product)` and `build_oomp_id(record.copy())` to pair SKU, shape and canonical ID. The snapshot at handoff contains 68 unique SKUs (28 rectangular, 6 square, 34 round) and one reference profile, leaving 67. Recompute these counts on resume. Old source folders include superseded IDs, including two folders ending in SKU 214. Use the active ID returned by population.
2. Start with SKUs 210–213, which share the 209 nominal footprint. Validate one complete build, then process the other rectangles, squares and rounds, including handled and colour variants. The taxonomy uses `rectangle` for both rectangle and square, and `circle` for round. Capacity and variant suffixes are part of the identity.
3. For each SKU, read its cached product fields, listing capture and PDF in `parts_source/<id>/`. Verify the official product listing, matching technical sheet when available, and at least one actual SKU photograph. A PDF labelled “Local OOMP capture” repeats listing data. The supplier's generic “Dimensions” entry can describe the shipping carton (for example 60 × 40 × 50 cm). Prefer the SKU-specific size, dimension diagram and explicit body/closed labels. Record units, source URLs and which dimensions include the lid or handle. Save the minimum supporting inputs under source control for offline regeneration.
4. If dimensions disagree, record the competing figures and why one applies to the model. Qualify photo-derived thickness, draft, radii and fittings. If the envelope or construction cannot be established, record the missing measurement or image against the SKU, then continue with the rest. Keep a resumable list keyed by SKU and canonical ID.

## Generate one family at a time

1. Add `models/systempak/<SKU>.json` with family, measured body and closed dimensions, material, photo-derived parameters and source references. Use the 209 ring profile where its construction matches. Keep wall thickness, corner radius, draft, collar, foot and tab adjustable in millimetres. For round pots use diameters and a rotational profile. For handled tubs model the visible attachment and state the handle position used for the envelope. Source each variant's colour and geometry independently. Model the hollow body and removable lid as separate solids in shared seated coordinates.
2. Register the profile in the appropriate `working_oomp_populate_detail_takeaway_container_*_systempak.py` helper. At handoff rectangle/square attaches a matching JSON automatically, round needs equivalent registration, and the original builder accepts only `systempak_rectangle`. Extend the shared dispatcher for new pot families while preserving dolly handling. Verify the populated source record and the canonical part record select the same profile.
3. **Adapt the 209 exporter before the first new SKU.** Its original export branch writes STL, Blender exports a GLB, and its source-only branch skips the renders while the README still links meshes. Use temporary geometry for Blender and solid checks. Publish the compact SCAD assembly with its body, lid and shared profile, a dimensioned SVG, lifted-lid and seated PNGs, provenance JSON and README. Link files actually produced. Preserve the existing 209 assets and keep all new SKU output directories free of STL, GLB, OBJ, 3MF and binary scene files.
4. Drive CAD, SVG and Blender from the same recipe through the packaging stage runner and `action_make_all.py`. Use the packaging dolly stages for a lightweight build example and the [tool project drawing routine](../../oomp_tool_version_5/working_svg.py) for orthographic projections. Dimension the plan and side/end views in millimetres. Identify the closed envelope and bare-body height explicitly. Put per-SKU changes in source profiles so regeneration preserves them. Keep reference acquisition separate from ordinary builds.

## Check each result

Run `python action_make_all.py --part <canonical_id>` from the project root on each registered SKU. Using temporary solids, verify one closed body and one closed lid, Z=0 at the base, the specified body extents, the seated lid height and absence of material overlap. The 209 builder checks extents to 0.025 mm and allows at most 0.01 mm³ intersection. These are numerical checks of the model against its declared inputs.

In each side or end elevation, draw the lid and wide rim at the top and the narrower foot on the floor. Check that both walls slope inward toward the base, matching the CAD profile so empty pots can nest. Open each SVG and both PNGs. Check the silhouette, tab or handle, lid seating, material and unobscured dimensions against that SKU's evidence. Validate relative README links. Repeat a representative build per family using only saved inputs, compare CAD and drawing contents and confirm equivalent renders. Verify the full catalogue with `python action_make_all.py`. Legacy Roboclick actions require the explicit `--legacy-actions` flag. Report built and evidence-blocked totals against the active queue, link example part pages, and summarize any per-family assumptions.
